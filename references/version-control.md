# Git版本记录

适用于修改本 Skill，不用于普通资料入库。用户已明确要求每次完成 Skill 修改都用 Git 记录版本；当前仓库位于本 Skill 根目录。首次建档及旧快照来源见 [版本历史](../VERSION_HISTORY.md)。

## 一轮修改怎样完成

1. 修改前检查仓库根目录、分支、工作区状态及已有标签，读取与本次相关的版本记录。已有未提交修改先辨清范围，不能替用户丢弃或把无关内容一并提交。
2. 按用户反馈修改所需文件；未完成的中间编辑保持工作状态，不冒称已发布。保留既有规则，只有有依据的变化才更新版本。
3. 验证本次真实变化：Skill格式、引用目标、必要时的真实案例效果。把验证范围和局限写入本次版本记录，不把语法通过当作行为质量通过。
4. 更新`VERSION_HISTORY.md`，记录版本、用户需求/问题、主要变化、验证结果及替代关系。版本号以仓库已有标签为准；通常小修增加patch，新能力增加minor，不把每次保存文件当作独立版本。
5. 只暂存本次Skill文件，用Git提交，并为完成版本建立带说明的标签。提交正文记录“原因、变化、验证”；多行说明从UTF-8文件或工具结构化输入传入，不拼接风险shell字符串。未经明确授权不推送。
6. 读回标签指向、提交文件范围及工作区状态，确认实际内容已入Git。交付版本号、commit短ID和记录入口；本轮产生的未提交内容仍需处理，不能报已完成。

一轮修改可以有中间提交，但至少有一个明确的完成版本标签。保存版本不表示用户认可了所有新Schema；确认状态与测试效果继续按协作迭代规则记录。

## 查询与比较

在本 Skill 根目录执行：

```powershell
git log main --oneline --decorate
git tag --list
git show v1.0.0:SKILL.md
git diff v1.0.0 v1.0.1 -- SKILL.md references
```

`v1.0.0`、`v1.0.1`是本次实际建立的完整版本。未来比较时换成要看的标签。回退时先检查当前修改并保留后续工作，按用户要恢复的范围生成可恢复的变更，不用强制reset清除工作。

## 已有历史文件的导入边界

Git首次建档前只有部分文件备份，按原字节导入独立历史快照标签；每个快照包含`SNAPSHOT_PROVENANCE.json`，记录源路径、SHA256、包含文件及导入时间。它们不混入当前文件凑完整旧版本，不回填旧提交日期，不属于main的完整发布链。

例如查看旧入口：

```powershell
git show history/20261010-before-collaboration:SKILL.md
git show history/20261011-before-reading-focus:SNAPSHOT_PROVENANCE.json
```

历史标签是部分文件证据，不能直接当完整Skill安装；完整恢复采用正式版本标签。
