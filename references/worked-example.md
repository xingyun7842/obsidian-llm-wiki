# 示范：一份材料怎样转成 Wiki

本文件是执行示范，不是已入库事实清单。依据默认库已归档的 Karpathy LLM Wiki 原文；只演示其明确提出的方法，不能把文中的效果主张当作已独立测试。下列路径是拟议产物，必须实际生成后才加入正式索引。

## 输入和页面决策

输入：默认库根目录 `Karpathy - LLM Wiki - 英文原文.md`。原件保留原位，不能为凑目录复制一份。

先假设检索未发现对应知识页（实际执行必须检索，不能沿用假设）：

| 候选页 | 决策 | 原因 |
| --- | --- | --- |
| `wiki/来源/Karpathy-LLM-Wiki-dc3efe98.md` | 新建来源页 | 记录整份文章主张与各章节位置 |
| `wiki/概念/LLM Wiki.md` | 新建概念页 | 本文中心概念，有定义、架构与工作方式 |
| `wiki/主题/资料理解的持久化.md` | 新建主题页，标记仅一份来源 | 对应用户长期问题：怎样复用已有理解，保留待验证效果 |
| Karpathy 人物页 | 暂不建 | 本次目的在方法，署名不足以支持完整人物页 |
| RAG 概念页 | 暂不建；已有则补关联 | 本文仅给对比性描述，不足以构建完整技术定义 |
| Obsidian 产品页 | 暂不建；已有则补角色说明 | 仅工具角色，不需要为每次提及建独立节点 |

这是示范中的判断，不强制每份材料都产出三页。

## 第二份材料到来时

假设新增一份有明确来源的测试报告，报告称其某组任务仍需大量回读原文：
- 原报告独立归档，创建第二个来源页；测试条件和数据按报告实际内容填写，不预设结果。
- 检索并复用已有“LLM Wiki”“资料理解的持久化”，不要创建“LLM Wiki 2”。
- 在主题页加证据比较，区分作者构想与测试观察；在概念页补适用限制，不能未经分析宣称两者必然矛盾。
- 索引新增第二个来源条目，更新原主题摘要；日志记录两个已有页的更新。

若只是重复提交同一篇文章，则复用哈希记录，检查处理是否完整，不重新创建这三页。
