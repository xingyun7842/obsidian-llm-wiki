# 查询与输出执行

1. 明确问题及必要范围；读索引并检索相关主题页。索引过大时先检索子索引；仅加载足够回答的页面。
2. 核对结论的来源与适用时间。证据充分则直接综合；证据不足、需精确引文或疑似冲突时，定向回读相关原文。不要默认重新处理整个库。
3. 未能补齐的证据明确列为未知；确需联网核验按当前可用工具及用户范围执行，新取得材料经入库流程才能作为持久证据。工具失败不能冒称核验。
4. 用最适合问题的表格、流程图、思维导图或短文回答，引用库内证据。用户要求只读时不写库；普通问答默认只读。要求“保存/沉淀/整理成知识页”时，才把有用的新综合写回主题页、索引和日志，不把每次聊天自动当事实入库。

## 成果选择

| 用户需要 | 交付 |
| --- | --- |
| 笔记/报告/流程图 | Markdown；流程图用 Mermaid |
| 比较或取舍 | Markdown 表格，必要时配图 |
| 演示内容/Marp 源稿 | 带 `marp: true` frontmatter 的 `.md`，页面用 `---` 分隔 |
| 真正 PPT/PPTX、PDF、HTML | 使用可用导出工具生成实际文件并验证；不能拿 Markdown 文件冒充成品 |

输出保存至 `outputs/`，知识性结论按授权回流主题页。Marp 导出为 PPTX 是工具能力，需要实际导出条件；不默认安装插件/依赖，不保证文字可编辑。可调用已安装且适合的演示文稿技能；条件不足时说明已完成的源稿与未完成的导出。

原文与四图中的“有价值回答回流”在本地实施为用户要求保存时执行；这样防止未经核验的聊天推断自动变成知识。必要时可以建议沉淀，不反复强迫用户确认普通入库写入。
