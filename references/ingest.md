# 入库执行

1. **识别材料、用途与重点**：列清本次材料、来源、格式和用途；区分支撑其他内容的底层框架与用户关心的高频问题，把已标重点记录到本次来源页或处理记录，尚未取得的材料先记定位线索。先检查用户是否标了重点（含已说出的关注问题）；没有则提示补充一次，同时继续通读，不等待标注才开工；已有重点不重复提示。读取 [阅读重点与方法提取](reading-focus.md)。支持当前工具可读取的文件/网页/文本；无法访问、密码保护、图片未识别等情况明确列出，不能编造已读。批量材料逐份记录状态，可分批续跑。
2. **归档与去重**：计算内容 SHA256，检索来源页中的哈希、URL或文件标识。相同内容且 `status: integrated` 时复用；只有归档记录或 `partial` 时接续整合。相同URL不同内容作为新版保留，两版关联。文本输入明确标为用户提供；不可取得网页原始字节时只保存可取得正文并记录提取方式。
3. **理解并定位**：按本次范围通读正文和图片，梳理主题、主要表达意图、模块和逻辑关系，需要时用思维导图或流程图呈现；结构明确后提炼底层方法/本质，没有方法时不强造理论；区分基础方法/原则、实例/模板、具体动作和结果。提取方法的目的、要素、关系、条件及原文位置，精读用户重点及其相关案例。查索引与有关主题，不扫描无关材料。图片、图表携带关键信息时单独检查；不能只看文本提取就声称完整理解，也不能以图片数量代替方法提取与整合。
4. **整合**：按 [页面与索引规范](page-schema.md) 先形成页面变更清单（可记录在本次来源页处理记录），列出候选页面、现有匹配、新建/更新/暂不建及理由；已确认且适用的规则直接执行；首次案例或新的重要结构选择，先展示代表性页面草稿与索引样例，按 collaborative-iteration.md 讨论后再固化。原文归档及已有规则覆盖的处理可继续，不把整项任务一概暂停。创建/补齐来源页；更新真正有关的实体、概念和主题综合页。写清方法如何落实为具体动作、交付物、判定标准和结果，原文实操与本库建议分开。对重点方法与实例写清双向关系：实例如何应用方法、具体写法如何反过来细化或限制方法；新增归纳标明来源性质，不冒称原文。新主张补充，重复主张加来源，矛盾主张并列记录来源、日期、条件和待核验项。页面数量由内容决定，不规定每份必须生成若干页。
5. **验证与提交状态**：修改前保存副本；逐项检查原文哈希、来源定位、相关内部链接和处理覆盖；用用户重点或实际用途检查能否找到方法内容、案例及其关联、原文位置，不能仅以归档/图片已读/节点数量报完成。来源页设为 `integrated` 或注明 `partial`/`archived` 及原因；更新主题导航，追加操作日志。处理中断时按已有状态续跑，不重复写入。

## 来源页最小结构

```yaml
---
type: source
source_id: 可读名称-短哈希
title: "实际标题"
source_url: "URL或空字符串"
raw_path: "相对路径"
sha256: "实际内容哈希"
captured_at: "实际时间含时区"
status: archived
topics: []
---
```

正文包含：材料摘要、关键主张与原文位置、适用范围、限制/冲突、关联主题、处理缺口。原文件与附件可在正文列出；多文件材料记录各文件哈希，不伪造单一哈希代表整个包。`integrated` 表示本次范围已整合且验收，不代表来源内容全部正确。

页面类型、正文模板、同义名复用、关系链接和索引条目遵循 [页面与索引规范](page-schema.md)。新增页面要有实质证据和完整导航路径；不能只填标题，或给每个出现的名词建立空节点。

日志条目包含操作ID、实际时间、输入ID、实际新增/更新文件、结果与未决项。恢复前核对操作ID和页面，避免重复追加同一操作。
