# 目标与组织

目标 vault：由使用者在首次使用时明确指定，后续在同一任务中复用已确认路径。公开版不包含默认私人路径。

用户明确指定其他库时按本轮要求执行；否则沿用默认库。路径不存在时，先查 Obsidian 本地注册记录及已知路径，不能静默创建同名库或误写入其他库。仍无法确定再向用户询问。

## 文件布局

| 路径 | 用途 |
| --- | --- |
| `知识库使用说明.md` | 本库约定、入口和调用示例 |
| `index.md` | 主题与来源导航；规模变大时拆主题子索引 |
| `log.md` | 追加记录入库、查询沉淀、维护的真实变更 |
| `raw/<来源ID>/` | 每份材料的原始文件、附件及明确标记的派生提取稿 |
| `wiki/来源/<来源ID>.md` | 来源元数据、处理状态、来源摘要与可引用位置 |
| `wiki/概念/<概念>.md` | 可复用概念的定义、机制、边界与来源 |
| `wiki/实体/<实体>.md` | 需要持续追踪的人、组织、产品或项目；同名消歧 |
| `wiki/主题/<主题>.md` | 跨来源整合、比较、条件、矛盾和未决问题 |
| `outputs/` | 用户要求的报告、图表、Marp Markdown、导出成果 |
| `.history/<操作ID>/` | 修改前副本；保留相对路径，避免同名覆盖 |

目录随实际内容按需创建。来源ID使用可读名称加短内容哈希或其他稳定标识；主题用自然名称。一个来源存一份，通过链接关联多个主题，不复制到每个分类。页面与索引按 [页面与索引规范](page-schema.md) 执行。对既有概念/实体落在主题目录的情况先复用，不为了目录美观迁移或复制。

方法来源：[Karpathy LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)。它是方法说明，不能声称是一套已自动运行的软件。使用者可以自行归档方法原文及工作流图；公开包不附带私人知识库中的材料。

普通主题变化使用主题页/文件夹/链接；只有用户明确需要权限、同步、保密边界或独立用途隔离时才考虑另建 vault。Obsidian 是阅读和编辑入口，Markdown 文件是持久存储。本 Skill 由支持 Skill 的代理调用执行，不是 Obsidian 常驻插件。
